# Trophy Room design system

Live style sample: `#/kp/trophy/style`. Screenshots in `screenshots/`.

## The idea

An old club's trophy room: engraved plaques, restrained brass, serif display
type. It reads as its own wing of the building while still clearly being the
same building, so every colour is either one of the app's existing tokens or
derived from them, and the serif is the one the Season review already uses.

Two treatments run through everything. **Praise** is brass on warm parchment.
**Shame** is tarnished grey-green and deliberately colder. The same component
renders both, so a title and a last-place finish are laid out identically and
only the metal changes.

Tables stay plain in both. Once there are numbers on the page, density and
legibility beat atmosphere.

## Tokens

All scoped to `.trophy`, so nothing leaks into the rest of the app. Defined in
`app/trophy.css` for light, overridden under `:root[data-theme='dark'] .trophy`.

| Token | Role |
|---|---|
| `--brass`, `--brass-bright` | Praise accent: eyebrows, captions, plaque seasons |
| `--plaque-top`, `--plaque-bottom`, `--plaque-edge`, `--plaque-lip` | Praise surface, its border and its inset highlight |
| `--tarnish`, `--tarnish-strong` | Shame accent |
| `--shame-top`, `--shame-bottom`, `--shame-edge`, `--shame-lip` | Shame surface |
| `--trophy-serif` | Display face, shared with the Season review |
| `--text-3` | Overridden darker than the app's own, see accessibility below |

## Components

All in `app/components/trophy/`.

| Component | Use |
|---|---|
| `Plaque` | The unit of record: season, title, subtitle, body, footnote. `tone="shame"` for the tarnished variant. |
| `RecordTable` | Caption, optional rank column, row headers, numeric columns, and a `note` for whatever bounds the numbers. `tone="shame"` available. |
| `OwnerChip` | An owner with that season's team name. `stacked` for narrow cells. |
| `SectionHeader` | Eyebrow, serif title, optional note. `as` sets the heading level. |

Two CSS-only patterns go with them: `.trophy-line` for a small-caps label beside
a value inside a plaque, and `.trophy-tile` for the landing page's hero strip.

## Rules

- **The owner is the subject, the team name is context.** Never the other way
  round. Team names change constantly; owners do not.
- **Ties are reported as ties.** Three owners share the title lead and two share
  the longest drought. Quietly picking one would be a lie.
- **Say "data unavailable".** `RecordTable` renders an `empty` message rather
  than an empty table, and nothing is ever interpolated.
- **No number is written into copy by hand.** Every figure comes from the shards.

## Accessibility

- Every foreground and background pair in both themes clears WCAG AA: 4.5:1 for
  body text, 3:1 for large text. This is why `.trophy` overrides `--text-3`.
  The app's own muted grey sits at about 3.2:1 on the warm plaque stocks, and
  this section leans on small print for qualifiers, spans and team names.
- Wings are real anchors with real `href`s, so they are keyboard-navigable and
  can be opened in a new tab or long-pressed. They are also the reason each wing
  is linkable from a league email.
- Tables carry a `<caption>`, `<th scope="col">` headers, and a `<th scope="row">`
  first cell, so a screen reader reads the owner before the numbers.
- Focus is visible on everything focusable, using the app's accent.
- The only transition is decorative and is disabled under
  `prefers-reduced-motion`.

## Layout

The Trophy Room uses the app's `wide` container (1180px) rather than the default
640px, because the record tables and the coming head-to-head matrix need the
room. Prose is held to a readable measure with `max-width` instead.

Mobile is the priority case: most people will open a link from a group email on
a phone. The hero strip stacks to one column, wings to one, and plaques to one.
Most tables fit 390px outright; the few dense enough to need it scroll
sideways, and `.trophy-table-wrap` draws a shadow at whichever edge has more
content, so the scroll is visible rather than something to discover.

## Copy

Blurbs live in `data/kp/trophy/copy.json`, generated by `src/trophy/copy.ts`
from computed facts. Every entry is written `status: "draft"` and renders only
on a local dev server. Change a status to `"approved"` to publish it; the
pipeline never rewrites an approved entry, and never deletes one.

The templates carry three rules learned the hard way: no gender is assumed for
anyone, a final that finished level on categories is described as level rather
than won, and a gap that runs the wrong way is stated in the terms it is true
in rather than printed as a negative number.

## Curated content

The Museum holds hand-entered entries. They are marked as curated everywhere
they appear: a broken rather than solid engraved rule along the top of the
plaque, and a row of marks giving `Curated`, then `Confirmed` or `Reported`,
then `Draft` where it applies. See `curated.md` for how to add one.

A curated entry may cite a team-week, and the build fails if the cited figure
stops matching the stored record. Hand-written does not mean unchecked.

## Checking it

```bash
node scripts/contrast.mjs
npx tsx src/trophy/qualifiers-report.ts
npx tsx src/trophy/spotcheck.ts
npx tsx src/trophy/matrix-check.ts
```

The second regenerates the record qualifiers and the evidence behind them. The
third traces displayed records back to the raw Yahoo payloads. The fourth proves
the head-to-head matrix sums to the all-time standings. Both exit non-zero on a
disagreement.

A note on which seasons count. The all-time standings and the matrix both include
every season whose regular season is arithmetically complete, which is the current
one as soon as its last regular-season week is scored. Reading Yahoo's `is_finished`
flag instead would leave the current season out of the standings while the matrix
counted it, and that is exactly how the two first came to disagree. Honours are
still only counted once the season itself has finished.

Walks every text node in the Trophy Room across both themes at phone width and
fails on anything below WCAG AA. It composites translucent backgrounds and
handles `color-mix()`, which computes to `color(srgb …)` with 0-1 floats —
both of those produced false readings before they were handled, in opposite
directions.

## Screenshots

Regenerate with the dev server running:

```bash
node scripts/screenshot.mjs --url 'http://localhost:5173/#/kp/trophy' \
  --out docs/trophy-room/screenshots --name landing \
  --size 1200x900 --size 390x844 --theme light --theme dark --full
```

It drives headless Chrome over the DevTools protocol and sets the stored theme
before the page paints, which no Chrome flag can do. It fails loudly if the
theme it asked for is not the theme that rendered.
